M3 review at HEAD `0f3ec98` (services/api/app/research + app/artifacts, apps/web artifact inbox, devices/windows-agent ArtifactOpener, scoped CORS). No High/Critical. One Medium (new), one Medium (new, forward-looking), rest clean/confirmed-fixed.

**Findings:**
1. Medium — `HtmlRenderer.render` (services/api/app/artifacts/renderers.py:142) feeds `canonical_markdown` straight into `markdown_lib.markdown()` with no HTML sanitization; python-markdown (>=3.6, `safe_mode` removed upstream) passes raw HTML/`<script>` through unchanged. `compose_canonical_markdown` (app/research/compose.py) embeds the user's `topic` (owner input, unescaped, up to 4000 chars) and provider `title`/`snippet` directly into that markdown with no escaping. Today only `DeterministicResearchProvider` is wired (no real risk), but `docs/SECURITY_MODEL.md` §6 explicitly names "prompt injection from websites/documents" as threat priority #1 and this render path is the literal seam `WebResearchProvider` (provider.py, stubbed) will plug into — untrusted website `title`/`snippet` will flow unescaped into HTML the moment that provider ships. Chain-of-concern: the Windows `desktop.open_artifact` capability (M3, same milestone) will `ShellExecute` a downloaded `.html` render directly in the owner's real browser (not a forced download), so this is a realistic self-XSS/exfil path once wired, not just a content-integrity nit. Fix: HTML-escape `topic`/`title`/`snippet` before embedding in the composer, and/or run renderer output through an HTML sanitizer (e.g. `nh3`/`bleach`) before storing the HTML render. Recheck when `WebResearchProvider` is implemented — should be a hard gate, not deferred again.
2. Medium — `ArtifactOpener` symlink defense (devices/windows-agent/src/PagentOS.SessionCompanion/ArtifactOpener.cs, `ResolveFinalTarget`/`Validate`) only re-resolves the reparse-point status of the **leaf file** being opened (`FileInfo(canonical).ResolveLinkTarget`). It does not walk ancestor path segments, so a directory junction/mount point planted **inside** an artifact root (e.g. `%LOCALAPPDATA%\PagentOS\agent\artifacts\subdir` junctioned to point elsewhere) would let a plain file physically outside every root pass containment (`IsUnderAnyRoot` on the textual canonical path) and then get opened for real (Windows resolves the junction transparently at `File.Exists`/`ShellExecute` time). No test exercises this (only leaf-symlink/`..`/sibling-prefix cases are covered in ArtifactOpenerTests.cs). Requires local write access to the artifact root (same-user malware/compromised process), so it's a defense-in-depth gap rather than remotely triggerable, but the class docstring explicitly claims junction protection that isn't fully delivered. Fix: walk each ancestor directory of `canonical` up to (not including) the matched root and reject if any segment is a reparse point, or resolve via `GetFinalPathNameByHandle`-equivalent on the open file handle and re-check containment on that.

**Confirmed clean:**
- All M3 DB access is SQLAlchemy ORM (`select`/`session.get`/`delete`, no raw SQL/string interpolation) — app/artifacts/service.py, app/research/activities.py.
- `/v1/tasks` and `/v1/artifacts` input bounded: `input` maxlen 4000, `source_limit` 1-8, `provider` allowlisted against `WIRED_PROVIDERS` (rejects unwired `"web"` with 422 — the future networked provider can't be silently invoked).
- READY-without-auto-read discipline genuinely enforced at the API layer: list endpoint has no `include` param at all (can't leak bodies even via query manipulation); single-artifact GET only returns `canonical_body` when `?include=body`; integration test asserts this both ways.
- `/renders/{fmt}` format allowlisted against `SUPPORTED_FORMATS` before any store access; render object keys are server-derived from `artifact_id.hex`/`version`/allowlisted-fmt only, no attacker-influenceable path component.

- Bundled fonts are genuine TrueType (`file` confirms valid sfnt tables), DejaVu license note present and accurate, no executable content, no host-path reads (embedded from a fixed `_FONT_DIR` under the package).
- apps/web artifact inbox: React JSX text interpolation only (`{a.title}`, `{a.executive_summary}`), no `dangerouslySetInnerHTML`; render links point at server-supplied `format` values only, no user-constructed URLs; single `NEXT_PUBLIC_API_BASE` var, no secrets.
- Repo-wide since M2 (`d132a0f`): no new tracked secrets, no new non-loopback binds (the one `0.0.0.0:9222` hit is a pre-existing M2 negative-test fixture in `services/browser/tests/unit/test_enrollment.py`, not new), no CI workflow changes in M3.
