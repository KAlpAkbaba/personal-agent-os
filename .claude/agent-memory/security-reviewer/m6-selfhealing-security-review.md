Full review: recovery-supervisor + app/selfhealing + staging/ demo target at HEAD `77ebf4a` (2026-09-01). Verdict: recovery-root independence PASS (stdlib-only supervisor, ADR-0023 memory boundary grep-enforced, path-traversal confinement tested and closed); sandbox-escape verdict FAIL — Critical.

**Critical (unresolved as of this review):** `DeterministicCodingBackend._rewrite_mapping` in `services/api/app/selfhealing/backends.py:246` splices `analysis.expected` (attacker-controlled via unauthenticated `POST /v1/selfhealing/incidents/ingest` → `evidence` JSON) into a Python source string literal via raw f-string, with no escaping — `f"({q1}{marker}{q1}, {q2}{analysis.expected}{q2})"`. The regression-test generator two methods below (line ~275) does the equivalent safely with `!r` (repr-based escaping); the patch generator does not. A crafted `expected` value can break out of the string literal, inject a top-level statement (e.g. `os.system(...)`), and re-close the surrounding tuple so the rest of the untouched file still parses — verified achievable by hand-tracing the regex substitution against the real checked-in demo file (`staging/target-service/releases-src/1.1.0/handler.py`, whose marker/class text is public in git). The independent `DeterministicReviewer` (backends.py) does not catch this: it only checks regression pass/fail, `ast.parse` success, presence of three function names, and absence of the literal string `"INJECTED-FAULT"` — no structural/semantic diff of what changed. End-to-end: forge/poison an incident's evidence via ingest (duplicate-fingerprint ingest **overwrites** `evidence_json` in place, `service.py:159-162` — no need to know an incident_id up front), then `POST /v1/selfhealing/pipeline/run` — the pipeline will build, review-approve, stage, and **promote the malicious code to the active production release**.

**Why this matters beyond the standing "no per-request API auth" hard gate** (tracked in `state/BUILD_STATE.json`): prior milestones (M4 speaker-verify, M5 memory/forget) exposed unauthenticated *data* mutation. M6 is the first milestone where the same unauthenticated-loopback pattern gates **code execution and deployment** — RCE via `pipeline/run` plus a self-installed backdoor delivered through the self-healing loop's own promote path. Flag this explicitly and with elevated urgency if [[m1-device-broker-security-review|any]] future milestone proposes wiring more privileged actions behind the same missing auth layer — this is the worst-case shape that gate is protecting against, now demonstrated concretely rather than theoretically.

**Fix direction given:** escape via `repr()` like the regression-test generator does (or rewrite via `ast`/structural edit instead of regex+string-splice); constrain error-class-like fields to an identifier-safe allowlist pattern; have the reviewer AST-diff the candidate against the broken release and refuse anything beyond the intended literal-value change; don't let a repeat ingest silently overwrite evidence for an incident already past `open`.

**Secondary findings (Medium/Low, same review):** unbounded `_get_or_record_introduced_release` lets forged ingest create fake `Release` rows and exhaust the 1000-attempt `_next_version` allocator for a component (DoS on self-healing, `service.py`/`pipeline.py:443-459`); `SelfHealingPipeline.run`'s `tempfile.mkdtemp` work_dir is never cleaned up on any path (`pipeline.py:230-241`, disk-exhaustion DoS given the endpoint is unauthenticated); no provenance/shared-secret distinguishing a real Recovery Supervisor report from a hand-crafted POST.

**Checked clean, worth remembering as durable facts about this codebase:** API server binds `127.0.0.1` only (`services/api/app/main.py:4` docstring, unchanged by M6); recovery-supervisor is genuinely stdlib-only and enforced by a grep-level regression test (`test_supervisor_project_is_stdlib_only`); ADR-0023's "engineering loop never touches owner-actor memory mutation" is enforced the same way (`test_pipeline_never_touches_owner_memory_mutation`) — both are cheap, high-value regression-test patterns worth checking still exist/still pass in later milestones rather than re-deriving from scratch. Manifest-digest signature verification before `activate` is explicitly deferred per constitution §6 (not a new gap — recheck when a milestone claims to close it).
