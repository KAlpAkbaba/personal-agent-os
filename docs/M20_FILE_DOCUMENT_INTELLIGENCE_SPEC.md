# M20 — File & Document Intelligence

Status: ENGINEERING CLOSED 2026-09-08 (ADR-0083; QUALIFICATION Stage 18; Cloud Core released as 092e56d). Decision record: ADR-0083.
Predecessors: M13 research artifacts (`app/artifacts`: canonical Markdown → PDF/DOCX/HTML/TXT renderers, object store), ADR-0076 (ID-based focus, the reference resolver), M19 (`object_focus`, the Digital Operator's `file.open` / `file.reveal`, `AuthorisedRoots`, the companion as the only process in the owner's session that touches files).

The owner's rule, in one line: **the system understands the owner's local documents and file structures with exact provenance — every answer names the file by identity and the place inside it, never by a fuzzy title.**

## 1. Where the files are and who reads them

The owner's files live on the owner's Windows machine. Cloud Core must not receive a copy of the owner's disk. Reading is a DEVICE capability family executed by the Session Companion inside owner-authorised roots (`AuthorisedRoots`: resolve-then-contain; default the owner's Documents / Desktop / Downloads / Pictures / Videos / Music and the operator fixture root), and the extracted text/structure (bounded) travels to Cloud Core over the existing command envelope together with the file's identity. Two identities are kept: `file:<…>` names a LOCATION, `doc:<…>` names a CONTENT VERSION (§2). Three filters keep privacy: the explicit allowlist of roots, a never-read list of secret-bearing names, and a per-request cap.

## 2. The device contract (binding; `packages/protocol/DEVICE_PROTOCOL.md` §6j carries the same text)

Family `documents` — six capabilities, advertised only with `OperatorEnabled` (the same gate as M19's operator family; the deployed 0.1.0 agent advertises neither): `file.search`, `file.locate`, `file.inspect`, `file.read`, `file.compare`, `document.extract`.

**Identity.** `file_id = "file:" + first 32 hex of SHA-256( lower(volume serial as 8 hex) + "|" + casefold(full resolved path) )`; `doc_id = "doc:" + SHA-256(bytes)`. A file record is always `{file_id, path, name, extension, size, mtime (ISO-8601 UTC), sha256?}` (`sha256` only when size ≤ 8 MiB). Kinds: `docx | xlsx | pptx | pdf | md | csv | json | source | txt | unknown` (`source` = .py .ps1 .cs .ts .tsx .js .sh .sql .yaml .yml .toml .ini .xml .html .css).

**Confinement.** Every path argument — search roots included — must resolve inside `AuthorisedRoots`, else error class `permission_denied`. Reparse points are never followed by a search. Names that carry secrets are never read: `.env*`, `*.pem`, `*.key`, `*.pfx`, `*.p12`, `id_rsa*`, `id_ed25519*`, `*.kdbx`, `secrets.json` → `permission_denied` (detail `secret_bearing_name`).

**Bounds.** Search ≤ 200 results, ≤ 20 000 directory entries walked, 10 s; read ≤ 65 536 chars; extract ≤ 65 536 chars of block text (`truncated: true` beyond, never a silent cut); files ≤ 50 MiB for extraction; PDF ≤ 200 pages (a longer PDF is refused before any page is read — `unsupported_format`, detail `page_bound` — unless a `page_range` of ≤ 200 pages is named); XLSX ≤ 2 000 rows per sheet. Device-side decompression and read bounds (ADR-0083 addendum 3): an OOXML package ≤ 64 MiB inflated by its central directory, ≤ 10 000 parts, no part above 1 MiB over 100:1; a PDF ≤ 32 MiB per inflated stream and ≤ 256 MiB per document; text-like files read as a 4 MiB prefix (`truncated: true`), JSON read whole ≤ 8 MiB; a bound is `unsupported_format` (detail `decompression_bound | page_bound | too_large`) with the numbers named, never an out-of-memory.

| capability | payload | result |
|---|---|---|
| `file.search` | `{roots?: [path], pattern: string (glob "*.pdf" or a name fragment "sözleşme"; casefold + diacritics-insensitive), extensions?: [".pdf"], max?: ≤200, modified_after?: ISO}` | `{files: [record], truncated, searched_roots: [path]}` |
| `file.locate` | `{file_id?, path?}` (one of) | `{file: record}` or error `not_found` |
| `file.inspect` | `{file_id?, path?}` | `{file: record, kind, is_text, encoding?, pages?, sheets?: [name], slides?, lines?, title?}` (headers only, no text) |
| `file.read` | `{file_id?, path?, offset?: 0, length?: ≤65536}` | `{file: record, text, encoding, truncated, total_chars}`; non-text kinds → error `unsupported_format` |
| `document.extract` | `{file_id?, path?, parts?: ["text","structure","tables"], page_range?: [a,b], sheet?: name, slide_range?: [a,b], max_chars?: ≤65536}` | `{file: record, doc_id, kind, title?, blocks: [{ref, kind, text, …}], structure, truncated}` |
| `file.compare` | `{a: {file_id?|path?}, b: {file_id?|path?}}` | `{a: record, b: record, same_content, size_delta, mtime_delta_s, kind, changed_refs, unchanged_refs, added_refs, removed_refs, summary}` (extractable kinds compare blocks by ref; text-like compare `L<n>` lines) |

**References (the strings an answer cites; `truth.json.reference_scheme` is normative).** DOCX: `p<n>` per non-empty paragraph in order (`kind = heading|paragraph`, `level` from the `Heading N` style), `t<n>` per table (`rows`). XLSX: `sheet:<name>!A<r>:<lastcol><r>` per non-empty row (tab-joined cell texts; a formula cell's text is `"=" + formula`, the block carries `formulas: {"B6": "B5*0.2"}`), `structure.sheets[{name, rows, columns}]`, `structure.formulas[{ref, formula}]`. PPTX: `s<n>` per slide (`title`; text = title then body paragraphs), `structure.slides[{index, title}]`, `structure.slide_count`. PDF: `p<n>` per page (whitespace-normalised), `structure.pages`. MD: `h<level>:<title>` per heading section (text = the section body). CSV: `r<n>` per line including the header, `structure.columns/rows/delimiter`. JSON: `$.<key>` per top-level key (compact JSON text), `structure.keys`. Source: `L<a>-<b>` per 40-line chunk, `structure.symbols[{name, line}]` from `def|class|function|public …(` lines, `structure.lines/language`. TXT: `p<n>` per blank-line paragraph.

**Error classes.** `invalid_argument`, `not_found`, `permission_denied`, `unsupported_format` (new in M20: `frames.py` `ERROR_CLASSES`, the device-protocol schema, the C# taxonomy), `timeout`. A format the device cannot parse answers `unsupported_format` with the reason, never an empty success.

**Extraction runs on the device**, in C#, behind per-format provider interfaces: `DocumentFormat.OpenXml` (MIT) for DOCX/XLSX/PPTX, `PdfPig` (Apache-2.0) for PDF, native code for the text-like kinds; both packages recorded in `docs/THIRD_PARTY_COMPONENTS.md`.

## 3. Cloud Core: the document intelligence (`app/documents/`)

- **`document_index`** (migration `20260908_0026_document_index`): `device_id, file_id, doc_id, path, name, kind, title, size, mtime, sha256, structure, blocks (≤ 64 KB, flagged when truncated), extracted_at, last_used_at`; unique `(device_id, file_id)` — the latest content version replaces the row. **No background crawling**: the index grows only from owner-initiated reads and searches; `index.refresh` re-extracts a known file on demand.
- **Retrieval is deterministic** (`retrieval.py`): Turkish casefold (both `I→ı` and `İ→i` accepted) + diacritics-insensitive token overlap, numbers and cell/page references matched literally, top-k blocks. The retriever chooses the refs; the cognitive backend, when configured, only rewrites prose around the same refs. **Every answer is `{speech, refs: [{ref, file_id, path, excerpt}], …}`; a claim without a ref is not an answer.** A question no block answers is an honest "bulamadım" naming what was searched, never an invented value.
- **Answers** (`answers.py`): `summarize` (kind-aware skeleton: headings / sheet names + totals row / slide titles / page firsts), `answer(question)`, `compare(a, b)` (the device's `file.compare` when both are on one device, else the two indexed block lists: changed/unchanged refs and the two texts of the first changed clause), `common_points(docs)` (terms present in every document, one ref per document per term), `references(question)`. The place is spoken in the owner's words: `p3` → "3. sayfa" (PDF) / "3. paragraf" (DOCX), `s4` → "4. slayt", `sheet:Ozet!A5:B5` → "Ozet sayfası, 5. satır", `h2:Kararlar` → "Kararlar bölümü", `r7` → "7. satır", `$.ses` → "ses anahtarı", `L1-40` → "1-40. satırlar". The file is named by `name`, and by `path` whenever another indexed document shares the title (ADR-0076's ambiguity rule).
- **Focus by identity**: `object_focus` kinds `file`, `document`, `folder` (additive to M19's table). Set on every read/extract (`document_read`), on a single search hit (`file`), on a folder pattern (`folder`), on `document.previous` (`document_previous`). "Bunu özetle" resolves the current document; "bir önceki belgeyle karşılaştır" the previous; no focus → `needs_clarification` "Hangi belge?". Two documents with one title and two paths are two ids.
- **Voice tools** (`tools_documents.py`): `file.search`, `document.read`, `document.summarize`, `document.answer`, `document.compare`, `document.inspect`, `document.common_points`, `document.previous`; intents `FILE_SEARCH`, `DOCUMENT_READ`, `DOCUMENT_SUMMARIZE`, `DOCUMENT_ANSWER`, `DOCUMENT_COMPARE`, `DOCUMENT_INSPECT`, `DOCUMENT_COMMON_POINTS`, `DOCUMENT_PREVIOUS`; context `CTX_DOCUMENT_FOCUSED`, `CTX_PREVIOUS_DOCUMENT`, `CTX_FOLDER_FOCUSED`, `CTX_SEARCH_RESULTS`. **There is no delete/move/write tool in M20** ("Bu dosyayı sil" reaches no tool and no device capability; the corpus proves it). Device selection by capability `document.extract`; none → `capability_missing` "Bu bilgisayarda belge okuma yetkisi yok" (the honest production answer until the owner's elevated agent update). Ledger rows `document.search/read/answer/compare`; receipts with subsystem `documents`.
- **Living Core**: `UiState.DOCUMENT_ANALYSIS = "document.analysis"`, metadata `{file, part, step?, refs?}`, contract version 5 (additive). Web: contract v5 tokens, the readout caption from published metadata only, the Cockpit `DocumentsPanel` (current / previous document, the last answer's refs, the honest empty state).

## 4. Fixtures and the automated qualification

`services/api/tests/fixtures/documents/` is generated deterministically by `scripts/tests/make-document-fixtures.py` (committed outputs; a re-run that changes nothing changes no bytes): `sozlesmeler/2025/sozlesme.docx` and `sozlesmeler/2026/sozlesme.docx` (one title "Hizmet Sözleşmesi", two paths, one changed clause: Madde 3, 30 → 45 gün), `butce-2026.xlsx` (sheet `Ozet` with the total 65000 and the formula `B5*0.2` in B6; sheet `Detay`), `sunum-q3.pptx` (7 slides; slide 4 "Müşteri Kazanımı"), `rapor.pdf` (5 pages; page 3 carries "Üçüncü sayfada yer alan bu cümle referans testidir."), `notlar.md` (`h2:Kararlar` → "Bütçe onaylandı"), `veri.csv` (`r7` → Kerem, İzmir), `ayarlar.json` (`$.ses` → `tr-TR`), `kod.py` (`hesapla` at line 4). `truth.json` (files with sizes/sha256, `reference_scheme`, ten `questions`, one `comparisons` entry, one `common_points` entry) and `expected/<path>.extract.json` (block for block what `document.extract` returns; `match` = `equals_normalised`, or `contains` for the PDF) are the oracle.

Gates: (device lab, real files under the fixture root) every fixture's extraction equals its expected extract; search/inspect/read/compare/identity/confinement/bounds as listed in ADR-0083; (Cloud Core) every `truth.json` question answered with the expected ref and excerpt, the comparison's changed refs exact, the common points with refs, the same-title pair named by path, current/previous focus; (voice) the corpus category `documents` ≥ 100 cases, forbidden count 0; (web) contract v5 + panel tests; TTS structural test on every spoken answer; loopback proxy on a sample.

## 5. Marks sought

Extraction and references PROVEN_REAL (real fixture files on this machine through the companion's real dispatcher); answers PROVEN_AUTOMATED (deterministic checks against the ground truth; the model's prose never asserted); voice routing PROVEN_AUTOMATED (corpus); loopback speech PROVEN_PROXY; the Cloud Core half on production PROVEN_REAL (release); the deployed-agent path PROVEN_PROXY until the owner's elevated update (item 28).
