# M27 — Creative Tools Operator

Status: ACTIVE (owner master directive 2026-09-07, M27 section; kicked off 2026-09-09 at the M26 gate). Decision record: ADR-0093.
Predecessors: M19 Digital Operator (`app.launch`, `window.*`, `ui.*` through UI Automation, `file.reveal`, the allowlisted terminal, `object_focus`), M20 documents (`file.search/inspect`), M22 artifacts (validation by independent readers), M24 Capability Genesis (an adapter for an application with a describable interface), M25 (structured plans as data, fixed drivers, inspection read-back, the visual comparison with `PIL`).

The owner's rule, in one line: **a creative edit is planned as data, executed through the most structured interface the installed application really offers, exported, reopened by an independent reader and compared with what was asked — and an application that is not installed or not licensed is named as such, never imitated.**

## 1. What is installed, and what that means (detected 2026-09-08, `docs/evidence/m27-m28-tool-detection-2026-09-08.json`)

- **Microsoft Paint** (classic `mspaint.exe`): present. It has no scripting interface; its document/object model is the bitmap file itself. M27 drives Paint two ways, in the directive's preference order: (1) the **document model** — the canvas IS a PNG/BMP: create/draw/text/shape/transform/crop/colour-adjust are performed on the file with `PIL` (the structured interface: deterministic, inspectable, testable) and Paint is opened on the result through the M19 operator so the owner sees it in Paint; (2) **application automation** through M19's UI Automation for what only Paint can do for the owner (open, save-as, the window) — never pointer drawing. "Bu resmi Paint'te yeniden çiz" therefore means: analyse the input image (`PIL`), build a `CreativePlan`, render it to a new file, open it in Paint, read the file back, compare. The Paint test of the directive (create a known canvas, draw controlled shapes/text, save, reopen, verify dimensions/colours/structure) is real on this machine and the runner.
- **Adobe Photoshop / Illustrator**: NOT installed (Creative Cloud 6.6 and Acrobat are; the owner's licence may add them later). M27 ships the **provider architecture** for both: `PhotoshopProvider` over Photoshop's ExtendScript/UXP scripting (a fixed `.jsx` driver executed with `-r` / the Creative Cloud scripting bridge) and `IllustratorProvider` likewise, each with its detection (`Photoshop.exe` / `Illustrator.exe` under `C:\Program Files\Adobe\…`, the registry), its capability list, and a lab that runs the real application ONLY when detected and licensed and otherwise reports `dependency_unavailable` with the detection facts. Never a licence bypass, never an authentication bypass: a provider that finds the application unlicensed says so.
- **Figma**: no desktop app; the browser path exists (M13 browser worker on the owner's Chrome session, M19). M27 ships `FigmaProvider` over the Figma REST API (read: files, nodes, exports — an owner token stored in DPAPI like every secret) and, for creation, the browser-design workflow through the M13 gateway on an owner-authorised Figma file only; without a token or an authorised file it is `dependency_unavailable`. No credentials are typed by the assistant anywhere.
- **Other image/design apps**: through Capability Genesis (M24) when they expose an interface description; otherwise refused honestly.

## 2. The plan (data, as M25)

`app/creative/spec.py` — `CreativePlan`: `tool ∈ {paint, photoshop, illustrator, figma}`, `source` (an owner image / reference image / design brief / an existing creative document — a focus ref or a path under an authorised root; the ORIGINAL is never overwritten: every output is a new file beside it, `<name>-pagentos-<n>.<ext>`), `operations[]` (≤ 64) from the CLOSED vocabulary the directive lists — `new {width, height, background}`, `open`, `inspect`, `draw {shape ∈ line|rect|ellipse|polygon, points, stroke, fill}`, `add_text {text, position, size, colour, font ∈ catalogue}`, `shape`, `transform {rotate|flip|scale}`, `color_adjust {brightness|contrast|saturation|levels within bounds}`, `crop {box}`, `background_remove` (a bounded, deterministic method: flood/threshold or a catalogued model behind a provider — the result measured, never assumed), `layer {add|merge}` (providers that have layers), `export {format ∈ png|jpg|svg|pdf, path}`; every text bounded and never spliced into a script (the `.jsx` drivers read a JSON plan); colours/sizes/positions bounded numbers.

## 3. The workflow (the directive's, measured at every arrow)

analyse input (`PIL` + the M13 vision seam where present: dimensions, colour histogram, dominant regions, text via the existing OCR seam if any — every fact recorded) → identify visual components → choose the application (the `ToolRouter`: the owner's word wins ("Paint'te", "Photoshop'ta", "Figma'da"); otherwise the source's kind and the installed set decide; an application not installed is a refusal that names the installed alternative) → plan → execute through the provider's most structured interface → inspect (read the output file with an independent reader) → export → **visual comparison** (`app/creative/compare.py`: target/reference/constraints vs the produced image — dimensions, colour distance per region, a TILED similarity measured with Pillow alone (ADR-0093 decision 4: numpy is not a dependency of this repository, and what is measured is named exactly - it is not SSIM and is not called SSIM anywhere), the presence of drawn shapes/text by masks; objective defects: wrong size, missing region, colour drift beyond tolerance, empty output) → discrepancy → correction (a follow-up plan, ≤ 3 rounds) → re-evaluate → the final result with its comparison metrics on the receipt.

## 4. Capabilities (only what the installed provider really supports)

`creative.open | new | inspect | draw | add_text | shape | transform | color_adjust | crop | background_remove | layer | export` — each provider advertises its subset; the Cloud Core exposes to the router only the union of the INSTALLED providers' subsets (Paint today: all but `layer`); a request for an unsupported one answers `capability_missing` naming the provider. The device side: the M19 operator opens/saves through the application; the file operations run under the documents family's roots; no new device capability beyond a `creative.export_check` that reopens the exported file with an independent reader on the device (the same bounds as `document.extract`).

## 5. Voice (the ONE router; corpus category `creative`)

Intents `CREATIVE_REDRAW` ("Bu resmi Paint'te yeniden çiz."), `CREATIVE_OPEN` ("Bunu Photoshop'ta aç." — routes to the provider, refuses when absent: "Photoshop bu bilgisayarda kurulu değil; Paint'te açayım mı?"), `CREATIVE_BACKGROUND` ("Arka planını kaldır."), `CREATIVE_ADJUST` ("Renkleri biraz düzelt."), `CREATIVE_CLEANUP` ("Logoyu daha temiz hale getir."), `CREATIVE_DESIGN` ("Figma'da buna benzeyen bir arayüz tasarla."), `CREATIVE_EXPORT` ("Bunu PNG olarak dışa aktar."). Route distinctions the corpus must prove with ZERO wrong-app routings in deterministic cases: Paint vs Photoshop vs Illustrator vs Figma vs image generation (an existing generation family, if any, else a clear refusal) vs a generic file open (M19 `file.open`): the tool word decides; a bare "Bunu aç." on an image focus is M19's `file.open`, never a creative tool; "yeniden çiz" is Paint's redraw. Negatives: "Orijinali sil" → no tool; overwrite of the original → refused; an app not installed → the honest refusal with the alternative; forbidden side effects 0 (no owner file modified — measured by hashing the source before and after every case).

## 6. The lab and the marks

Paint lab (this machine + the runner, `mspaint.exe` present on both): a known 320×240 canvas with a red rectangle, a blue ellipse and the text "Merhaba" is produced through the Paint provider, saved, opened in Paint through M19 (the window observed, then closed), reopened by `PIL`, and its dimensions, the colours at known points and the shape masks verified; the comparison metrics asserted; a deliberate mismatch (the wrong colour) detected and corrected in one round. Photoshop/Illustrator labs: run the detection; when absent, assert the honest `dependency_unavailable` with the facts (a real run when the owner installs them — the same lab, no code change). Figma lab: the REST provider against a recorded fixture (no network in tests); the browser path through the M13 fake gateway. Marks: Paint PROVEN_REAL; Photoshop/Illustrator/Figma PROVEN_PROXY (provider + lab; the truth spoken); the visual self-correction PROVEN_AUTOMATED; voice PROVEN_AUTOMATED (route distinctions 0 wrong); the Living Core (UI contract v12 `creative.activity`, the Cockpit "Yaratıcı" panel with the before/after images) PROVEN_AUTOMATED; the Cloud Core PROVEN_REAL (release) with one Paint round trip on production through the owner's device (item 28 permitting).

## 7. Security

- The owner's originals are never overwritten; outputs are new files under the documents roots; nothing is deleted.
- No script is generated from owner or model text: the `.jsx`/Figma drivers are fixed files reading a JSON plan; text is drawn as pixels by `PIL` or passed as a JSON string to a driver.
- Licences and logins are the owner's: the Adobe providers refuse when unlicensed; the Figma token is DPAPI-stored and never printed; the browser path uses only an owner-authorised file.
- The exported file is validated by an independent reader before it is presented; images are bounded (≤ 8192×8192, ≤ 50 MiB).
