# M7 Security Review — 2026-09-01

Independent review of the Evolution Engine (base + owner acceptance delta) — the highest-blast-radius subsystem in the product, since it writes and promotes code. Companion: independent test-engineer verification (PASS on every acceptance bullet and delta subsection, with one defect of its own, below).

**No Critical. One High, fixed same-day. The independent acceptance verification found a second defect of the same class, also fixed.**

## Findings and dispositions

| # | Severity | Finding | Disposition |
|---|---|---|---|
| 1 | High | Deny-by-default permission approval was a self-service rubber stamp: `IndependentSkillReviewer._approve_permissions` approved **any** requested network/filesystem/device/secret grant the moment `creation_reason.authorized_asset` was a non-empty string — a value the requester supplies, with no Authorized Asset Registry (an M8 deliverable) to verify it against. An unauthenticated caller could obtain a `production` capability carrying a fabricated "owner-authorized, independently reviewed" permission record, corrupting the audit trail the constitution requires to be truthful. Not exploitable for code execution today (fixed 5-operation generator + unconditional forbidden-import/call list), but a privilege-escalation path the moment a non-deterministic generator, an I/O-capable operation, or any consumer that trusts manifest permissions appears. | **Fixed**: new `app/evolution/authorization.py` introduces an `AuthorizationProvider` seam. Approval now requires a **verified** authorization whose recorded scope **covers** every requested grant. The default `NullAuthorizationProvider` verifies nothing, so with no registry every grant is refused and skills still reach production with empty grants (deny-by-default holds). `StaticAuthorizationProvider` supplies explicit authorizations for tests/local use; M8's registry implements the same interface, preserving the constitution's owner-policy path without Evolution touching the security root. The review payload now records the provider, the decision reason, and any unauthorized grants. Tests: an asserted asset reference alone is refused (over HTTP too), a grant exceeding the asset's recorded scope is refused, and the owner-authorized path still reaches production when a verified source exists. |
| 2 | High (from acceptance verification) | The composition-first gate validated the decision trail's **shape**, not its truth: a well-formed but fabricated composition entry (which `CapabilityComposer` never produced) unlocked full generation and registration. ADR-0025 claims this evidence is auditable; self-reported data trusted by shape is not. Not reachable via the public API today (routes always compute the trail server-side), but it is the gate the resolution-order guarantee rests on. | **Fixed**: `require_composition_attempted` now optionally takes a composer and **re-derives** the claim against live registry state; the pipeline always passes one. A fabricated "insufficient" claim is refused when the composer independently reports the request composable. This also closes a real race: a capability registered after the trail was written now makes composition sufficient, and generating code would violate the resolution order. Regression test reproduces the verifier's exact attack. |
| 3 | Low | `CapabilityDispatcher` hand-rolled its subprocess environment instead of reusing the module's allowlist + secret deny-list assertion. | **Fixed**: dispatch now uses `build_isolated_env`, so a later widening of the allowlist cannot silently skip the secret check. |
| 4 | Low | No rate limit / in-flight cap on `/v1/evolution/gaps/{id}/resolve`, which spawns several subprocesses per call, on an unauthenticated surface. | **Tracked** under the standing API-auth hard gate in BUILD_STATE, now explicitly extended to the evolution endpoints (they can create and promote code). Per-request work is bounded (case/list/text caps, depth limit, timeouts). |

## Explicit verdicts (post-fix)

- **(a) Generated-code injection: not present.** Choke-point + splice-point token validation on every value reaching generated source; the only executable logic emitted is fixed source selected by an allowlisted key, never request-derived. Hostile-payload tests cover the M6 Critical's payload classes.
- **(b) Sandbox escape: not present** within the threat model. Sandbox roots overlapping the recovery supervisor, API source, alembic, config, state or docs are refused at construction, and every written path is re-checked.
- **(c) Promotion integrity: sound.** `register()` is the only path to production and requires evaluated status, passing evaluation **and** independent review, per-edge lifecycle evidence, and verified permission approval; no endpoint can forge evaluation/review/lifecycle payloads. The two evidence-trust gaps (permissions, composition) are closed by findings #1 and #2.
- **(d) Permission model — honest answer: enforcing at generation/evaluation/review time, advisory at runtime.** An unconditional forbidden-import/call list blocks I/O regardless of grants (stronger than the grant system itself), and grants are now verified against a real authorization source. There is still **no OS-level runtime confinement** at dispatch (no network namespace, filesystem jail or job object) — moot for today's pure-transform operations, and recorded as the prerequisite before any I/O-capable generated operation or non-deterministic generator is enabled.

## Clean areas (verified)

Supply chain (offline catalog only, digest recomputation, exact pins, install scripts refused outright, reviewer re-scans the manifest the generator actually emitted); resource and recursion limits (depth refused before any registry work; Windows rlimit gap honestly reported as `wall_clock`); boundary correctness (the delta's operational-grant clarification relaxes only the prose heuristic — structural target/kind/prefix signals still refuse recovery-root self-modification unconditionally); memory boundary guard-tested; no new tracked secrets; no non-loopback binds.
