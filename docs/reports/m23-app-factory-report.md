**BUGS FOUND / FIXED (regression tests for each)**
1. Cloud Core: a new matcher named `_app_open_match` silently shadowed M19's function of the same name and surfaced as a `ValueError` deep in `resolve_intent` — caught live by the corpus, the whole family renamed `_appfactory_*`.
2. Cloud Core: `test()` moved `state` to `tested`/`failed`, so `stop()`/`status()`/`exercise()`/`open()` treated a still-running project as stopped — `run_port` is now the truth of "up right now" (`test_stop_still_works_after_test_moved_state_to_tested`).
3. Device: `<port>` tripped the manifest's composition-character check, so every template run command was refused.
4. Device: `node ../x.js` answered `validation_error` instead of `permission_denied`.
5. Device: the run log was opened `FileMode.Create` while the previous run's handle was still held — a second `project.run` collapsed into an IOException; the log now closes when the run ends and opens after the slot/port checks.
6. Device: a just-stopped run holds its listener for a few ms — the free-port check tolerates a releasing port (2 s) while still refusing a genuinely held one.
7. Device lab: `Process.HasExited` turns true before a node child releases its cwd handle, leaving empty run folders — the lab waits on the process object and retries the delete.
8. Web: the receipt parser never read the device's own `project.test` shape (`exit_code, passed, failed, report_tail`); the deduplicated refusal sentence named only the last chip sharing a reason.
