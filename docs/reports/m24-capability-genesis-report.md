**BUGS FOUND / FIXED (regression tests for each)**
1. The realtime-session tool-catalogue test pinned the exact set of tools `create_app` wires into a voice session and had not been updated for the four `capability.*` tools - found by the track's own full-suite run and fixed on the branch.
2. **The vacuous verification** (independent verification pass): `_verify` compared only the fields the mutation's output and the read-back's output share, so a description sharing none reported `verified` having compared nothing. Closed in two layers, two regression facts.
3. **The authorization gate that asked the wrong question** (security review, HIGH, live PoC): the owner's authorization was resolved by the document's own self-reported name and never passed through `covers()`. Closed, three regression facts.
4. **The approval race** (security review, MEDIUM): no compare-and-swap in `approve()`. Closed with a conditional UPDATE, one regression fact.
5. **The origin nobody decided** (security review, MEDIUM): a description could name this system's own ports or a privileged port. Closed, two parametrized regression facts over every reserved port.
6. **The dead `{id}` template** (security review, LOW): accepted at parse, never substituted, failing at run time. Refused at parse now.
7. The corpus category shipped 71 cases where spec section 6 binds at least 100 - disclosed by the track rather than padded, and closed at integration with ten base cases that widen real coverage (109 now).
8. **The container that would not start** - found by the release itself, which is what a release is for. `GenesisRuntime.service` created its skills root, and `create_app` builds that service eagerly, so every process start touched the filesystem; the evolution runtime's default skills root was `parents[4]/skills/generated`, which is the repository root in a checkout but the FILESYSTEM root in the image, so the container computed `/skills/generated` and died with `PermissionError` before uvicorn could load the app. api-green never answered health and the harness rolled back with production untouched. Fixed in d6bb9d5: the runtime creates no directory at startup (the publish path already makes what it needs, which is why M7 evolution always started cleanly), and the default root only trusts `parents[4]` when `services/api` really sits beneath it, otherwise resolving inside the app tree (`/srv/pagentos/skills/generated`, owned by the container user). Three regression facts, including building the real application object with every `mkdir` failing the way the read-only image did.
