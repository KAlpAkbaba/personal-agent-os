All five closed (ADR-0084 addendum 2, migration 0029 `read_back_session_id` / `read_back_turn` / `confirmed_by` / `last_error`): the read-back is an explicit act bound to its session and turn; a voice confirmation must come from the SAME session and a STRICTLY LATER turn resolved by the deterministic router (`confirmation_not_owner` for a model-issued mutation with no owner turn behind it; `not_read_back` for another session); a REST confirmation is the owner's own authenticated act; an atomic compare-and-swap moves the row to `sending`/`committing` before any provider call (two threads confirming the same draft: exactly one send, the other `already_sent`); per-message parse isolation with MIME depth/part bounds (`unparseable` counted and spoken); RRULE occurrences capped and the window clamped; header control characters stripped at parse time, recipients validated, a typed `send_failed` receipt with the row back to `read_back`. Verified sound by the review: no secret in logs/receipts/ledger rows, TLS with verification everywhere, snippets only at rest, attachments never fetched, the fakes bound 127.0.0.1 only, the corpus negatives real, the web posts to exactly the six routes with no HTML rendering of mail content.
