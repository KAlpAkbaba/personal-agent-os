## 2026-09-02 — M12 Realtime Voice Foundation, tracks A + E (offline gate)

- `ProviderCapabilities` gained the realtime vocabulary from the M12 spec §2 (speech-to-speech, full-duplex, barge-in, end-of-turn mode, tool calling, transports, ephemeral credentials, input formats, interrupt latency class) with "not offered" defaults, so all M4 TTS/STT adapters are untouched. `select_conversation_provider` is a pure, tested function: hard requirement, then semantic end-of-turn, then WebRTC, then the configured preference — never a name (a provider *named* like the preferred one but lacking a capability is rejected in a test).
- `RealtimeProvider`/`RealtimeSessionHandle` now carry audio in/out sinks, structured timestamped events, barge-in cancel, tool-result submission and per-session credential minting; the M4 fake still satisfies them. New deterministic full-duplex **simulator** (`app/voice/simulator.py`) on a virtual clock, embedding the M4 control FSM (ordering + `STOP_WORDS` reused), with controllable first-audio / end-of-turn / hesitation-guard / barge-in-stop / preamble / tool-done timings, synthetic PCM frames, tool calls and network loss.
- Realtime session service (`app/voice/realtime_sessions/*`, migration 0011, `/v1/voice/realtime/...`): capability-selected provider, credential minted through the adapter (the vendor key is asserted never to leave the server or reach a row), Turkish persona + executive-assistant instructions, tool manifest, idempotent tool relay on `(session, call_id)`, long-running tools with a Turkish preamble completed over the broker WebSocket sideband (queued and replayed when no socket), client timing/state events, continuity `attach` that moves the media leg between owner sessions, `voice_*` audit rows with ids/timings only. Health check `voice_realtime`. Route-table sweep extended: every new verb is protected.
- Turkish intent resolver (`app/voice/intents.py`): dur / devam / tekrar oku / ikinci maddeyi tekrar oku / sonraki-önceki-ilk-son madde / sonraki bölüm / biraz daha yavaş-hızlı / özet geç / detaya gir / burayı atla — normalised with the tr-TR normaliser (so "2. maddeyi" works), filler-tolerant (şey/yani/hani/ııı), token-based (so "durum" never stops), resolved against session + narration state, bridged into the narration engine's durable cursor and speed through the M4 command machine.
- Benchmark harness (`app/voice/realtime_bench.py`): mic→uplink, end-of-turn→first audio, barge-in→stop, tool preamble, tool-done→speech, gap and tool-silence detection, false-barge count; targets recorded with their basis as targets, never claims. Gate test proves the simulator meets them AND that a slow/gappy/guard-less simulator fails them. Eval set extended with the M12 terminology, ı İ ğ ş ç ö ü phonetics, a hesitation set and the intent utterances.
- Tests: +~125 unit (1323 → 1448 green), +1 integration (real schema + PostgreSQL-enforced idempotency). ADR-0035 records the reversible decisions. Not in this change: the real speech-to-speech adapter (track B), desktop/web audio clients (C/D); acceptance stays real-only.

## 2026-09-01 — Real-environment qualification, stage 1: Session-0 IPC identity

- The M1 review's one open finding is closed (ADR-0028), which was the gate on installing the Windows Service. The pipe was ACLed to whoever created it — correct while both halves ran as the same user, wrong the moment the service becomes LocalSystem in Session 0 — and there was no mutual authentication beyond that ACL. Now four layers, each with its own audited refusal: an explicit owner-SID DACL; `FILE_FLAG_FIRST_PIPE_INSTANCE` so a squatter cannot make the service the second instance on its own name; peer admission on account, Windows session and image path read from the kernel rather than from any frame; and a per-connection id plus strictly increasing sequence so a retired or repeated frame is refused. The companion refuses any pipe not owned by an account trusted to host a service, and connects at Identification level so the service may identify it but never impersonate it.
- 19 adversarial tests covering the six attacks the owner named — fake pipe, wrong SID, wrong Windows session, replayed IPC, stale session credentials, forged companion identity — plus the wiring itself. 110 agent tests total.
- Independent security review found a **Critical in the fix**: the shipped companion constructed its runtime without a policy and silently inherited developer trust, which trusts a pipe owned by the owner's own account. Since UAC splits integrity level rather than identity, any process in the owner's session could have driven the companion on an installed agent. `ServiceMode()` existed nowhere outside the tests. Fixed by changing defaults rather than by remembering to pass an argument, with the active posture logged at every start. Third occurrence of "built, tested, and not wired" in this project (M8, M9, here).
- `docs/QUALIFICATION.md` is new and is the honest record: every criterion is `PROVEN_REAL`, `PROVEN_PROXY` or `NOT_YET_PROVEN`, a proxy result is never written up as real, and the entry that over-claimed was corrected in place rather than quietly.
- Prepared, not yet run, because each needs exactly one owner action: `install-device-service.ps1` (self-contained publish, Program Files with write denied to non-administrators — which is what makes pinning the companion binary meaningful — ProgramData state, LocalSystem service, companion logon task), `verify-device-service.ps1` (reports the criteria only a real install can prove, and refuses to pass vacuously), `bootstrap-owner-credential.ps1` (refuses to run under transcription; writes nothing to disk), `secret-store.ps1` (masked prompt, DPAPI, owner-only ACL, injects into a child process's environment so no decrypted file exists), OpenTofu for a Hetzner host with no public application port, and CI jobs for the Windows agent, the recovery supervisor and secret hygiene.

## 2026-09-01 — M9 native mobile + owner identity complete

- Owner identity (ADR-0027): opaque bearer sessions minted from a file-backed credential root that deliberately is **not** a database table, so a restored or rebuilt database neither resurrects nor destroys the owner's ability to authenticate; hash-only storage with constant-time comparison, TTL + idle timeout, refresh rotation, a panic control that revokes everything, throttled credential exchange, and a token-free append-only audit that records the precise refusal while telling the caller only the coarse class. Recovery runs on the host (`python -m app.identity.recover`), not through the API the credential protects.
- **The standing API-authentication hard gate, deferred since M0, is closed.** Every memory, voice/narration, self-healing, evolution, security and broker endpoint now requires an owner session. The unauthenticated surface is exactly five endpoints, each with its own credential (health; loopback-only one-time bootstrap; credential exchange; device enrollment by owner-minted single-use token; the device WebSocket handshake) — and that list is enforced by a test that walks the live route table and dependency graph, so a new unprotected route fails the suite rather than shipping quietly. The suite contains no authentication bypass: every test holds a real token from the real service.
- Mobile surface: push provider seam with registrations, artifact-ready announcement, notification inbox, share/export in both formats, narration cursor checkpointing across the mobile lifecycle (background, interruption, token expiry, network loss), and device-bound sessions that die with the device across the whole REST API rather than just its WebSocket. A headless reference client (`clients/reference`) drives the entire mobile contract against the real API in CI.
- Web shell owner sign-in: credential exchanged once and dropped, session token attached by a single `apiFetch`, 401 handled in exactly one place; the localStorage trade-off is stated in the module rather than hidden.
- Independent security review: no Critical, no High; two Medium and three Low, all fixed — the announcer stamped `announced_at` before delivering (now one transaction spanning select-lock, deliver, stamp, commit); `require_scope` was implemented but wired into zero routes, so scopes narrowed nothing (now structural: bare `require_owner_session` refuses a scoped session, so forgetting a scope declaration fails closed); loopback guards failed open on an unidentifiable peer; device revocation now revokes sessions before the device row so a crash between the two transactions fails safe; a corrupt identity root refuses cleanly and can never be overwritten by bootstrap. docs/reviews/M9_SECURITY_REVIEW.md; ADR-0027 + security addendum.
- Integration suite now takes a PostgreSQL advisory lock so two concurrent runners serialize — the flakes seen in this project traced to a second process (another test run, or a live dev API server whose announcer sweeps the shared `tasks` table every 5s), not to the code under test.
- Independent verification: five of the six acceptance bullets proven outright against a live server — including an adversarial authentication sweep (missing/garbage/malformed headers, `X-Forwarded-For` spoofing, injection-shaped tokens, path traversal, forced expiry: all coarse refusals, no reason leaked, no plaintext token anywhere in the database or logs) and a live device-revocation run with a real EC P-256 key. Proof boundary stated rather than blurred: real push delivery to a phone and microphone/realtime capture under OS backgrounding are proven-by-proxy and stay owner actions.
- Test-infrastructure defect found by that verification and fixed here: E2E tests that hard-kill worker subprocesses left PostgreSQL backends behind (Docker's port forwarder holds the socket open, so the server never sees the peer go), and the suite eventually failed with "too many clients already" in whichever test asked for a connection next. Now: graceful stop where the kill is not the property under test (`tests/integration/procs.py`), plus `max_connections` and server-side TCP keepalives in the dev compose. A full integration run now leaves zero idle backends.
- Totals: 1323 unit + 94 integration API tests; full M0–M9 gate 12/12 PASS.
