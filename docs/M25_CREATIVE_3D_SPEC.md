# M25 — Unity / Blender / 3D Creation

Status: CLOSED 2026-09-08 (ADR-0088 + addendum 1; QUALIFICATION Stage 23; Blender PROVEN_REAL, Unity PROVEN_PROXY until owner item 32; Cloud Core release: `PROVEN_REAL` (the release and the surface)). Decision record: ADR-0088.
Predecessors: M19 Digital Operator (`AuthorisedRoots`, the allowlisted terminal, `object_focus`), M23 App Factory (a bounded Job Object child under a `Projects` root, the fixed command allowlist, the ProjectFiles policy, "free text never lands in code"), M22 (structured specs validated by independent readers), M13 (the object store for renders).

The owner's rule, in one line: **the assistant creates and changes 3D scenes through the tools' own scripting interfaces, proves every change by reading the scene back from the tool and rendering it, and never claims control of an application it cannot actually drive.**

## 2. The scene plan (the structured spec, spec-first as M22/M23)

`app/creative3d/spec.py` — `ScenePlan`: `tool ∈ {blender, unity}`, `project` (a slug under the 3D root), `scene` (a slug), `operations[]` from a CLOSED vocabulary — `create_scene`, `add_primitive {kind ∈ cube|sphere|cylinder|plane|light_sun|light_point|camera, name, location[3], rotation[3], scale[3]}`, `transform {name, location?, rotation?, scale?}`, `set_material {name, color[4], metallic?, roughness?}`, `set_camera {name, look_at?}`, `set_light {name, energy}`, `attach_script {name, script_id}` (Unity only; `script_id` from a fixed catalogue of shipped C# scripts, never model-authored C#), `render {width, height, engine}`, `inspect`. Every name a closed-alphabet token, every number bounded, ≤ 64 operations per plan. Free text never lands in code (the M23 rule, structurally enforced at the splice point): the plan is serialised to JSON and the tool-side driver reads JSON — no Python or C# is generated from owner words.

## 3. The drivers (the tool's own scripting interface, never mouse control)

- **Blender** — `blender --factory-startup -b [<scene.blend>] --python <driver.py> -- <plan.json> <out.json>` (the factory settings are never optional: without them the run loads the owner's own installed add-ons, measured 2026-09-08 to hang the editor outright; the scene file is absent on a project's first run and `scene.blend` on every later one): the shipped driver (`app/creative3d/drivers/blender_driver.py`, a fixed file in the repository, stdlib + `bpy`) executes the plan operations, saves the `.blend`, renders when asked, and writes an **inspection** (`out.json`: every object with type/location/rotation/scale/material colour, the camera, the lights, the render path + sha256 + size) — the read-back is what the tool reports, never what the plan asked.
- **Unity** — `Unity.exe -batchmode -nographics -quit -projectPath <root> -executeMethod PagentOS.SceneDriver.Run -planPath <plan.json> -outPath <out.json> -logFile <log>`: the shipped `Assets/PagentOS/Editor/SceneDriver.cs` (a fixed file copied into the fixture project at creation) executes the plan through the Editor API (`GameObject.CreatePrimitive`, `Transform`, `Renderer.sharedMaterial`, `Light`, `Camera`, `AddComponent` for catalogued scripts), saves the scene, renders a still with `Camera.Render` to a `RenderTexture` → PNG, reads the console/compile errors (`out.json.errors[]`), and writes the same inspection shape.
- Both run as a **bounded Job Object child** through the device's M23 `ProjectRunner` (`project.run` with a new allowlisted runtime pair `blender --factory-startup -b …` / `Unity.exe -batchmode …` under the 3D root; Unity's own limits: ≤ 10 min, ≤ 4 GiB, the log bounded) — the device `projects` family gains the two runtimes and a `scene.inspect` capability that returns `out.json` bounded; nothing else changes on the device.

## 4. The closed loop (spec §"closed loop" of the directive)

owner intent → `ScenePlan` → the driver creates → render/preview → **inspect** (the tool's read-back) → compare with the plan's constraints (`app/creative3d/compare.py`: every requested object present with the requested transform within tolerance, the material colour within tolerance, the camera aimed at the target within 2°, the render file present and non-trivial — checked by an independent reader: `PIL` opens the PNG and measures that it is not uniform) → modify (a follow-up plan) → rerender → validate. A mismatch is reported naming the object and the axis; never "done" without the inspection.

## 5. Voice (the ONE router; corpus category `creative3d`)

Intents `SCENE_CREATE` ("Unity'de boş bir sahne oluştur", "Blender'da yeni sahne aç"), `SCENE_ADD` ("Bir küp ekle", "Blender'da küre oluştur", "Bir ışık ekle"), `SCENE_TRANSFORM` ("Küpü sağa taşı", "Küreyi iki kat büyüt"), `SCENE_LIGHT` ("Işığı ayarla", "Işığı artır"), `SCENE_CAMERA` ("Kamerayı nesneye çevir"), `SCENE_RENDER` ("Render al"), `SCENE_INSPECT` ("Sahnede ne var?"); the tool word (`unity` / `blender`) resolved from the utterance, else the current focus (`object_focus` kind `scene`), else a clarification. Tools `scene.create | scene.add | scene.transform | scene.material | scene.light | scene.camera | scene.render | scene.inspect`; every receipt is the inspection read back ("Küre eklendi: Kure, (0, 0, 0), yarıçap 1; sahnede 3 nesne"); numbers spoken are numbers read back. Negatives: "Sahneyi sil" / "Projeyi sil" → no tool; a request naming the owner's real project → refused (only fixture projects under the 3D root); an operation outside the vocabulary → clarification. Forbidden side effects 0 measured by inspecting the fixture project after every case.

## 7. Security

- Never mouse/keyboard control of either editor; never the owner's own projects (the 3D root is the only authorised root for these runtimes; a `.blend`/project path outside it is refused before any process).
- No model-authored Python or C#: the drivers are fixed repository files with sha256 pinned in the manifest; the plan is data; `attach_script` only from the catalogue.
- The runtimes are allowlisted as argv (M23's `ProjectManifest` discipline): `blender --factory-startup -b <file under root> --python <the shipped driver> -- <plan under root> <out under root>`; Unity's argument list likewise; a plan or output path outside the root refused; the Job Object bounds; the render size bounded (≤ 1920×1080); the inspection bounded (≤ 256 KiB).
- The PNG is validated by an independent reader before it is stored or shown.
- ONE closed vocabulary of nine words for the STEP of the loop (`creating`, `applying`, `rendering`, `inspecting`, `verified`, `unverified`, `mismatch`, `unavailable`, `failed`), on every surface a client reads or the owner hears: `scene.activity`'s `metadata.state`, the `/v1/scenes` row, the receipt, and the spoken `scene.status` (in Turkish, in the same words the Cockpit draws). Never a database row's own word — the row keeps its own vocabulary for its own purposes and `wire_step()` derives the step from what it recorded, including the comparison it stored, so a row with no comparison is `unverified` rather than verified over nothing. The Cloud Core and the web each spell the list once and a test reads the other side's file to hold them together (`services/api/tests/unit/test_scene_activity_vocabulary.py`); they drifted once, and the Cockpit could not read a single successful run, showed no controls on any row, and read an English token out loud.
